# Финмодель УК «Спартак» — правила работы

Финансовая модель управляющей компании сети футбольных академий:
прогноз сети, EBITDA, денежный поток, экономика франшизы, мерч, лагеря,
выплаты ФК, сценарии и чувствительность.

## Жёсткие правила

1. **Партнёры и школы считаются отдельно.** Один партнёр держит несколько
   школ. Правило «1 партнёр = 1 школа» запрещено.
2. **Постепенный набор детей.** Новая школа выходит на мощность по этапам
   1–12 мес. / 13–24 мес. / зрелая. Заменять набор полной загрузкой нельзя.
3. **БДР и БДДС не смешиваются.** Начисление и деньги живут в разных
   блоках `02_Модель`; расхождение между ними объясняется складом, займом
   и авансами, а не «подгоняется».
4. **Все ручные вводные — на листе `01_Вводные`.** Новых вводных на других
   листах не заводить.
5. **Экономика не меняется без подтверждения.** Представление, навигация,
   форматы, подсказки — можно. Формулы, ставки, коэффициенты — только с
   явного согласия владельца модели.
6. **Модель правится скриптом, не руками.** Любая правка — код в `tools/`,
   который детерминированно превращает исходник в результат. Тогда правку
   видно в диффе, можно откатить и пересобрать.

## Контракт правки

Каждое изменение модели описывается пятью пунктами — в коммите и в
`docs/Журнал_правок.md`:

```
Проблема       что не так и где (лист!ячейка)
Причина        почему так получилось
Решение        что именно меняется
Финансовый эффект   дельта EBITDA / cash / детей / школ (числом)
Проверки       какие тесты это ловят
```

Правка без замера финансового эффекта не принимается: любое движение
формулы проверяется прогоном до и после.

## Инструменты

```bash
python3 tools/extract_model.py                    # карта модели -> build/
python3 tools/extract_model.py --cell 02_Модель!B44   # формула + связи ячейки
python3 tools/extract_model.py --sheet 07_Мерч        # карта одного листа
python3 tools/extract_model.py --grep "роялти"        # поиск по формулам и текстам

python3 tools/run_model.py --tag база             # прогон, срез в build/runs/
python3 tools/run_model.py --scenario негативный  # прогон сценария
python3 tools/run_model.py --set '01_Вводные!B58=0.07' --tag ндс7
python3 tools/run_model.py --compare база негатив # построчная дельта

python3 tools/build_user_friendly.py              # V8.8 -> V8.9
```

`build/` не версионируется — пересобирается за полминуты.

## Как устроена модель (то, что уже выяснено)

- 24 листа, ~118 500 заполненных ячеек, ~114 100 формул, 203 имени.
- Горизонт — 60 месяцев, столбцы `B:BI`. Даты строит `02_Модель!B3`
  от старта `01_Вводные!B7`.
- `02_Модель` — витрина: БДР (строки 17–47), БДДС (50–72), контроль
  оборотного капитала (74–78). Своих расчётов почти не содержит, тянет
  из `04`–`10`.
- `19_Расчет_аналитики` (4857 строк) — расчётный движок: **три полные
  копии модели**, по одной на сценарий, с шагом 1012 строк
  (негативный ~717, базовый ~1729, позитивный ~2741). Лист `03_Сценарии`
  читает все три одновременно, поэтому не зависит от переключателя.
- **`01_Вводные!B192` хранит текст** — «Негативный» / «Базовый» /
  «Позитивный», а `B194` переводит его в номер:
  `=IF(B192=C197,1,IF(B192=D197,2,3))`. Подстановка числа не ломается
  явно — она молча проваливается в последнюю ветку и даёт позитивный
  сценарий. `run_model.py` поэтому сверяет посчитанный номер с
  запрошенным и валит прогон при расхождении.
- Пересчёт делает LibreOffice Calc (openpyxl формулы не считает).
  Полная книга пересчитывается ~12 секунд.

## Открытые вопросы (решает владелец модели, не агент)

1. Закрытие школ. 2. Конверсия продажи в открытие. 3. Каникулы по роялти.
4. Премия Евгения — gross или полный бюджет. 5. Налоги и страховые взносы.
6. Пошкольный расчёт действующей сети. 7. Финальный график закупок склада.

Агент может подготовить по каждому вариант с расчётом последствий, но не
выбирает сам.
